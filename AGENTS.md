# AGENTS.md

## Purpose

This project starts from planning documents. Agents working in this repo should treat them as the source of truth for product intent, scope, and direction.

## When To Read The Planning Docs

Read the planning docs before making or changing anything related to:

- gameplay systems
- combat rules
- progression
- narrative
- worldbuilding
- UX or terminology tied to the game concept
- roadmap or scope decisions

Re-read them when a task could conflict with earlier decisions, when requirements seem ambiguous, or when proposing new systems.

## Planning Table Of Contents

- [Vision Document](./docs/planning/vision.md)
- [Product Requirements Document (PRD)](./docs/planning/prd.md)

## Working Rules

- Keep implementation aligned with the planning documents unless the user explicitly overrides them.
- If code, tasks, or notes drift from the current vision or PRD, update the relevant planning document or flag the mismatch clearly.
- Keep these docs current as the project evolves. Assumptions go stale quickly; update links, terminology, scope, and decisions when they change.
- Prefer small, traceable edits so the planning docs remain useful as living references rather than historical snapshots.
